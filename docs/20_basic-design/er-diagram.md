## 2. 関連の一覧

| 親 | 子 | カーディナリティ | 意味 |
|---|---|---|---|
| topic_sets | sentences | 1 : N | 1つのお題セットに複数のお題文が属する |
| topic_sets | sessions | 1 : N | 1つのお題セット(難易度)で複数回セッションが行われる |
| users | sessions | 1 : N | 1人の利用者が複数回セッションを行う |
| sessions | miss_records | 1 : N | 1セッションで複数のミス(キー単位)が発生しうる |
| sessions | session_kana_counts | 1 : N | 1セッションで複数のかな1拍が出現する |

## 3. 設計上の判断

### 3.1 ミス記録はキー単位のイベントとして持つ(P1未決事項への回答)

`requirements.md` FR-04 で未決だった「記録の保存粒度」をここで確定する。**キー入力1回=1行**で記録する(セッション単位の集計ではない)。同じかな1拍で複数回ミスした場合、`miss_records` には複数行入るが、`kana_occurrence_no`(同一セッション内で、そのかなが何回目の出現かを示す連番。かなの種類ごとに1から数え直す)が同じ値になるため、分析時に「拍1回のミス」として数え直せる。`getMissAnalysis` は全セッションを横断して集計するため、数え直す際は `COUNT(DISTINCT (session_id, kana, kana_occurrence_no))` のようにセッションをまたがない形で DISTINCT を取る必要がある(session_id を落とすと、別セッションの同じかなの同じ出現回数が1件に潰れてミス回数を過少計上する)。

### 3.2 `session_kana_counts` を持つ理由(ミス率・正解率の分母)

FR-10(1)「かな1拍別のミス率」・FR-10(4)「文字種別の正解率」には**分母**(そのかな/文字種が何回出現したか)が要る。分母を毎回 `sentences.reading` から算出しようとすると、かなの種別判定ロジック(清音/拗音/撥音/促音/長音の切り分け)をバックエンドにも実装することになり、`system-architecture.md`(ADR-002: ロジックの実働実装はフロントエンドのみ)と矛盾する。そのため、判定ロジックを持つフロントエンドがセッション終了時に「このセッションでどのかなが何回出たか」を集計して送り、バックエンドはそれをそのまま保存する設計にした。

### 3.3 FR-10(3)「直前のかな1拍別のミス発生率」の分母は近似する

厳密には「あるかな X の直後に何らかのかなが来た回数」が分母だが、専用の集計テーブルは持たない。`session_kana_counts` の X の総出現回数で代用する(セッション末尾の1拍分だけ、本来の分母よりわずかに多く数える誤差が生じるが、個人利用の分析用途では許容する)。
