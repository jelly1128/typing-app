# 画面設計

## 1. 画面一覧

| 画面ID | 名称 | 対応 UC |
|---|---|---|
| S-01 | 名前入力画面 | UC-00 |
| S-02 | ホーム画面(練習設定) | UC-01 |
| S-03 | タイピング画面 | UC-02 |
| S-04 | 結果画面 | UC-03, UC-05(一部) |
| S-05 | 履歴・自己ベスト画面 | UC-04, UC-05 |
| S-06 | ミス分析画面 | UC-06, UC-07 |

UC-07(改善アドバイス)は独立画面を持たず、S-06 内のセクションとして表示する(use-cases.md UC-07 のトリガーが「分析結果画面でアドバイスを見る」であるため)。

## 2. 画面遷移

```
S-01 名前入力
  │ (名前確定)
  ▼
S-02 ホーム(練習設定) ◀────────────────┐
  │ (開始)                    (もう一度/戻る) │
  ▼                                    │
S-03 タイピング                          │
  │ (終了条件達成)                        │
  ▼                                    │
S-04 結果 ───────────────────────────┘
  │ (履歴を見る)
  ▼
S-05 履歴・自己ベスト ───(分析を見る)───▶ S-06 ミス分析
```

- S-02 のヘッダーから S-05・S-06 へ直接遷移できる(いつでも履歴・分析を見られる)
- `POST /api/users` で得た `userId` と名前は、ブラウザの localStorage に保存する(リロード・再訪問後も保持するため)。起動時に localStorage を読み出し、値があれば S-02 から始まる。値がない場合(初回起動、または localStorage が空)のみ S-01 を経由する。ストアの具体的な構造は P3 `class-design.md` で確定する
- **userId が存在しないとき(2026-08-26追記、REV-008 A3対応)**: `userId` 系 API(`/api/sessions` `POST`、`/api/users/{userId}/...` 全て)が 404(`nonfunctional-design.md` NFR-09)を返した場合、フロントエンドは localStorage の `userId`/名前をクリアして S-01 へ強制的に戻す。これにより、DB再構築等で `userId` が失効しても利用者が自力で復旧できる状態にする

## 4. 自己ベスト・履歴0件時の挙動(P1 B2 対応)

P1 ゲート①レビューで指摘された未決事項(B2)をここで確定する。

| 画面 | 対象データが0件のときの表示 |
|---|---|
| S-04 結果画面(自己ベスト比較) | 今回が該当難易度の初回セッション(比較対象なし)の場合、「自己ベスト比較」は表示せず、代わりに「この難易度の初回記録です」と表示する |
| S-05 自己ベストセクション | 選んだ難易度のセッション結果が0件の場合、数値の代わりに「まだ記録がありません。練習を始めましょう」を表示し、S-02 への導線ボタンを出す |
| S-05 履歴一覧セクション | 全体のセッション結果が0件の場合、「まだ記録がありません」を表示し、S-02 への導線ボタンを出す |
| S-06 ミス分析画面 | セッション自体が0件の場合、4種の集計セクションはすべて「分析にはある程度の練習記録が必要です」を表示し、改善アドバイス(FR-11)も生成しない。セッションはあるがミス記録が0件の場合、FR-10(1)(2)(3)(かな別・誤りパターン別・直前かな別)は同じ空状態表示にするが、FR-10(4)(文字種別正解率)はミスがないため全文字種100%として通常どおり算出・表示する |

「0件」と「値が0(ミスなし等)」は区別する。「0件」はレコード自体が存在しない状態(上表の空状態)、「値が0」(例: あるパターンの誤りが1度も発生していない)は通常の集計結果としてそのまま表示する(該当行を単に出さない、または0件と表示する)。
