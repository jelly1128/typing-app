# ADR-001: 認証機能を MVP から除外する

## ステータス

採用(charter.md の当初方針を維持)

## 背景

P1-01(ユースケース洗い出し)で、利用者から「認証周りの学習もしたい」という意見が出た。charter.md では既に「認証(Spring Security + JWT)は学習価値が高いが +2〜3 セッションかかるため MVP 外とし、完走を優先する」と決めていたため、方針を維持するか変更するかを検討した。

## 検討した案

| 案 | 内容 | 見送り理由 |
|---|---|---|
| A. 当初方針どおりスコープ外 | 利用者識別は名前入力のみ(UC-00)。認証は拡張バックログに記録 | (採用) |
| B. 簡易識別を UC 化するのみ | パスワードなしの名前選択を UC として明文化する | A に統合(UC-00 として実施) |
| C. 本格認証を MVP に組み込む | Spring Security + JWT を P1 の時点で組み込む | +2〜3 セッションかかり、charter.md の最大リスク「デプロイまで到達せず未完で終わる」(6章)と正面から矛盾する。1人開発・週1〜2セッションという制約(5章)の下では完走の確度を下げる |

## 決定

案 A を採用する。認証機能(ログイン・パスワード管理等)は MVP に含めない。利用者識別は UC-00(名前を入力する)の簡易識別のみとする。

本格認証への学習意欲自体は否定しない。charter.md 3.2 のスコープ外バックログに残し、**MVP 完走後(P9 以降)の拡張候補**として扱う。

## 影響

- `docs/10_requirements/use-cases.md`: UC-00 を追加(認証なしの名前入力)
- `docs/00_project/charter.md`: 3.2 に追記(2026-08-23)。3.1 の MVP リストは変更なし(認証は元々含まれていない)
