# ADR-004: 長音「ー」はハイフンキー"-"1つで確定する

## ステータス

採用(P1 ゲート①済みの `requirements.md` FR-02 / `glossary.md` の記述を上書きする)

## 背景

P1(ゲート①通過済み)の `requirements.md` FR-02 受け入れ条件5、および `glossary.md` の「長音「ー」」の定義は、いずれも「直前の母音の表記に応じた延長表記を正解とする」としていた。

P3-01(`logic-spec/romaji-automaton.md`)で受理表を疑似コードまで具体化する過程で、この方式には次の問題があることが判明した。

- 直前の拍が複数のローマ字表記を持つ場合(例: 「し」=si/shi/ci)、どの表記の母音を延長するかで組み合わせが増える(si→sii、shi→shii等)。受理パターンの生成規則が複雑になり、テストベクタ化・実装のどちらにも見合わない
- 実在の日本語ローマ字入力タイピングソフト(e-typing 等)の多くは、長音記号を専用の "-" キー1つに割り当てており、学習者にとってもこちらの方が直感的

P3-01のドラフトではこの問題を理由に "-" キー方式へ変更したが、上流の `requirements.md` / `glossary.md` を修正せずに下流(P3)だけを変更してしまっていた(P3中間レビュー REV-009 A1で指摘)。CLAUDE.mdの運用ルール「差異が見つかったら先に設計書を直す」に反する状態だったため、本ADRで正式に決定を記録し、上流文書を修正する。

## 検討した案

| 案 | 内容 | 見送り理由 |
|---|---|---|
| A. ハイフンキー"-"1つで確定する | 長音を、直前の拍の綴りとは独立した固定の1拍として扱う | (採用) |
| B. 直前の母音表記を繰り返す(当初のP1記述) | 例: こーひー→ "koohii" のように直前拍の母音を延長する | 直前拍の表記ゆれ(例: し=si/shi/ci)と組み合わさると受理パターンが爆発的に増え、実装・テストベクタ化のコストに見合わない。学習者にとっても「どの表記を延長すればよいか」が分かりにくい |

## 決定

案 A を採用する。長音「ー」は文脈(直前の拍が何か)に関わらず、常に "-" キー1つの入力を正解とする。

## 影響

- `docs/10_requirements/requirements.md` FR-02 受け入れ条件5を修正する
- `docs/10_requirements/glossary.md` 「長音「ー」」の定義を修正する
- 上記2点の変更を `docs/00_project/change-log.md` に CL-006 として記録する
- `docs/30_detail-design/logic-spec/romaji-automaton.md` 5.3の「(要確認)」表記を外し、確定表記に改める
