# ADR-005: フロントエンドのスタイリングは Tailwind CSS を採用する

## ステータス

採用

## 背景

P7-00a(未決事項解決)で、frontend のビジュアルデザイン対応(`wbs.md`P7着手時確認事項)を進めるにあたり、CSS フレームワークを選定する必要があった。`screen-design.md`はビジュアルデザインをスコープ外としており、具体的な見た目・スタイリング手段は未決定だった。Kazuki の希望は「見た目も上げたいが、使い勝手(ユーザビリティ)を優先する」。

## 検討した案

| 案 | 内容 | 見送り理由 |
|---|---|---|
| A. Tailwind CSS | ユーティリティクラスを組み合わせてスタイリングする | (採用) |
| B. PrimeVue(Vue 向け UI コンポーネント集) | ボタン・入力欄・トースト通知等をアクセシブルな部品として利用する | 部品の完成度は高いが、見た目の自由度がテーマの範囲内に制限される。Kazukiの「見た目も上げたい」という希望との相性でAに劣ると判断 |
| C. プレーンCSS + 自作デザイントークン | フレームワークを入れず、CSS変数で色・余白等を定義し自前でスタイリングする | 学習コストは一番高いが、初のスタイリング作業でゼロから設計するには工数がかかりすぎる。CLAUDE.local.mdの「学習目的の個人開発、初心者寄り」という前提とは噛み合うが、P7の見積もり規模(1〜2セッション)に対して重い |

## 決定

案 A(Tailwind CSS)を採用する。実務での採用例が多く学習価値が高い一方、ボタン・入力欄等のアクセシビリティ(フォーカス状態・キーボード操作等)は自前で付与する必要があるため、P7の実装タスクでユーザビリティ(使い勝手優先というKazukiの方針)を意識して個別に対応する。

## 影響

- `frontend/`に`tailwindcss`を導入する(P7の実装タスクで対応)
- 各Viewコンポーネントの既存マークアップにTailwindのユーティリティクラスを適用する形でスタイリングする
- ボタン・入力欄・フォーカス状態等のアクセシビリティは実装時に個別に確認する(自動で付与されないため)
