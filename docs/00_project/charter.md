# プロジェクト憲章

## 1. プロジェクトの目的

日本語タイピングアプリを開発する。ただし**アプリの完成は3つの目的のうちの1つ**に過ぎない。

| # | 目的 | 達成の判定 |
|---|---|---|
| 1 | SI 企業風のウォーターフォール工程を一通り体験する | 全工程の成果物が `docs/` に揃い、各ゲートのレビュー指摘 A が全件クローズしている |
| 2 | Claude Code の機能(commands / agents / skills / rules / hooks)を実地で整備する | `.claude/` に全種類が1つ以上動作する状態で存在する |
| 3 | build → deploy → document のフルループを一度通し切る | 公開 URL を他人に渡せ、README が書かれている |

## 2. プロジェクト全体の完了条件

> **公開 URL で他人がタイピングでき、記録が DB に残り、`docs/` に要件〜テストの全成果物が揃い、工程別の見積り/実績ズレ率が数値で出ている状態。**

## 3. スコープ

### 3.1 MVP(P1 ゲート①で正式確定)

| # | 機能 |
|---|---|
| 1 | お題の日本語文を表示し、ローマ字入力を判定する(複数表記許容: し=si/shi/ci、ん=n/nn、っ=子音重ね) |
| 2 | セッション実行(お題 N 文 または 制限時間) |
| 3 | リアルタイム表示(確定文字 / 次に打つ文字 / ミス位置) |
| 4 | 結果算出(KPM、正確率、所要時間) |
| 5 | 結果を PostgreSQL に保存 |
| 6 | 履歴一覧 + 自己ベスト表示 |
| 7 | お題セット管理(DB 保持、難易度別)。難易度は利用者が UI 上で選択する |
| 8 | ミス傾向分析(文字別ミス率・誤りパターン・直前文字との関連)+ 改善アドバイス表示 |

> 2026-08-23 追記(P1-02): #4 の結果算出に Net KPM・Raw KPM・Consistency(打鍵間隔のばらつき)・文字種別正解率を追加した。詳細は `docs/10_requirements/requirements.md` FR-06 参照

**ユーザー識別は「名前入力のみ」**とする。認証(Spring Security + JWT)は学習価値が高いが +2〜3 セッションかかるため MVP 外とし、完走を優先する。

### 3.2 スコープ外(拡張バックログ)

理由なきスコープ外は後で判断できなくなるため、各項目に理由を付けて記録する(P1-04)。

| 項目 | 理由 | 拡張候補としての優先度 |
|---|---|---|
| 認証(ログイン・パスワード管理) | 個人専用アプリで必須ではなく、実装に +2〜3 セッションかかり完走優先の方針(6章)と相反する(ADR-001) | 中(学習興味あり。P9以降) |
| ランキング | 単一利用者アプリのため他者比較の需要がない。前提として複数ユーザー管理・認証が必要になる | 低 |
| お題投稿(お題文の追加・編集 UI) | 開発者によるシードデータ投入で十分。UI/API 追加のコストに見合わない | 低 |
| WebSocket 対戦 | リアルタイム対人戦は実装コストが大きく、「正確さ向上のための原因分析」という目的とも無関係 | 低 |
| 英語モード | ローマ字オートマトンとは別の英単語判定ロジックが必要になり、P3 の設計が分岐する | 低 |
| かな入力(JIS配列等) | ローマ字入力前提の設計と別のキーマッピング実装が必要 | 低 |
| モバイル対応(スマホ画面のレスポンシブ対応) | タイピングは物理キーボード前提のアプリであり、スマホでの利用需要がない | 低 |
| テーマ切り替え(ダークモード等) | 見た目のカスタマイズはアプリの本質(正確さ向上の原因分析)と無関係 | **中(拡張候補として明示的に関心あり)** |
| 結果の SNS 共有・エクスポート(CSV 等) | 個人専用アプリのため共有・エクスポートの需要がない | 低 |
| 苦手文字に基づく自動お題生成 | ミス分析(FR-10)の自然な拡張だが、お題生成ロジックの新規実装が必要で MVP の手間を超える | **高(拡張候補として明示的に関心あり。苦手文字分析の活用先として優先度が高い)** |

> 2026-08-23 修正: 「苦手キー分析」は当初スコープ外としていたが、本アプリの中心コンセプト(正確さ向上のための原因分析ツール)と直結するため MVP(3.1 の #8)に格上げした。
>
> 2026-08-23 追記: P1-01 で「認証も学びたい」という意見が出たが、完走優先のリスク方針(6章)と整合させるため当初方針(認証はスコープ外)を維持する判断とした。本格認証(Spring Security + JWT)は P9 以降の拡張候補として保持する(ADR-001)。
>
> 2026-08-23 追記(P1-04): モバイル対応・テーマ切り替え・SNS共有/エクスポート・苦手文字に基づく自動お題生成の4件を新たにスコープ外として明文化した。うちテーマ切り替えと自動お題生成は拡張候補としての優先度を明記した。

テーブル 4〜5(`users` / `sentences` / `typing_sessions` / `session_results` / ミス記録用テーブル(暫定、P2 で確定))、API 6〜8 本、画面 4〜5(トップ / タイピング / 結果 / 履歴 / ミス分析(暫定))

## 4. 技術スタック

| 層 | 選定 | 備考 |
|---|---|---|
| フロント | Vue 3 + Vite + TypeScript + Pinia | |
| バック | Java 25 + Spring Boot 4.x + Maven マルチモジュール | Spring Boot 4.0 が Java 25 を first-class support |
| DB | PostgreSQL 16 + Flyway | ローカルは Docker コンテナ |
| デプロイ | Render(Web Service + Managed Postgres) | Fly.io が次点。AWS は +3 セッションのため P9 送り |

### 4.1 モジュール構成の方針

`backend/typing-core/` を**言語非依存の純粋ロジック**として物理的に分離する(Maven マルチモジュール)。

- 単一モジュール + パッケージ分離より初期設定が +0.5 セッション重いが、依存の混入をビルドレベルで強制的に防げる
- 中核は**ローマ字入力受理オートマトン** — 外部依存ゼロの状態機械。テストしやすく、他言語への移植題材として理想的
- 仕様は `docs/30_detail-design/logic-spec/` に**言語名を出さない疑似コード**で書く
- 正しさは `shared/testdata/` の共有テストベクタ JSON で検証する。**他言語実装は同じ JSON を通すことで同値性を保証する**

## 6. リスクと対策

| リスク | 対策 |
|---|---|
| **デプロイまで到達せず未完で終わる** | P2.5 で Walking Skeleton を先に本番へ出す。デプロイを最後のご褒美にしない |
| 実装が膨らんで工程が終わらない | P5 が 8 セッションを超えたら履歴画面を切って P6 へ進む |
| 「情熱の先払い見積もり」で着手が遅れる | セッション冒頭の `/ty-plan` で必ず当日ゴールを1行に固定する |
| 設計とコードが乖離する | 差異を見つけたら**先に設計書を直す**。差異は `change-log.md` に記録する |
| 見積もり精度が上がらない | 毎セッション `estimate-actual.md` に見積/実績/要因を追記し、P8 で補正係数を算出する |
