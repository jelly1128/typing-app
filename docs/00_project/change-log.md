# 変更管理票

工程を先に進めた後で前工程の成果物を直した記録。**設計とコードが乖離したまま進まないための仕組み。**

## 運用ルール

- 実装中に設計との差異を見つけたら、**コードを書く前に設計書を直し**、その事実をここに1行残す
- 「なぜ設計時に気づけなかったか」を書く。これが次のプロジェクトの設計観点になる
- 却下した案そのものは ADR(`decisions/`)に書く。ここは**確定済みの成果物を変更した記録**に限る
