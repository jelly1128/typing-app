# レビュー(2026-08-23)

対象: `docs/10_requirements/requirements.md`, `docs/10_requirements/use-cases.md`, `docs/10_requirements/glossary.md`, `docs/00_project/charter.md`, `docs/00_project/decisions/001-auth-out-of-scope.md`

P1 要件定義 ゲート①の正式レビュー。過去の中間レビュー(REV-001, REV-002)の結果は前提とせず、上記対象ファイルの現時点の内容のみを根拠に独立して判定した。

## 重要度A(必須)

該当なし。

以下を確認し、いずれもブロッカーとなる欠陥は検出しなかった。

- charter.md 3.1 の MVP 項目(#1〜#8)は、それぞれ requirements.md の FR-01〜FR-13 のいずれかに過不足なくマッピングされている(#1→FR-01/FR-02、#2→FR-05、#3→FR-03、#4→FR-06、#5→FR-07、#6→FR-08/FR-09、#7→FR-13、#8→FR-10/FR-11。FR-04・FR-12 は各々 #8・「名前入力のみ」注記に対応する補助的要件として妥当)
- FR-01〜FR-13 の「対応UC」は全て UC-00〜UC-07 の実在する ID を指しており、UC-00〜UC-07 は全て少なくとも1つの FR から参照されている(カバー漏れなし)
- NFR-01/02/09 の「対応FR」も実在する FR-ID を指している
- 文書内に存在しない ID(例: FR-14 や UC-08 等)への参照は見つからなかった
- charter.md 3.2 のスコープ外項目(認証・ランキング・お題投稿・WebSocket対戦・英語モード・かな入力・モバイル対応・テーマ切替・SNS共有/エクスポート・苦手文字自動お題生成)はいずれも FR/UC 側に紛れ込んでおらず、特に認証除外(ADR-001)とお題投稿除外は FR-12・FR-13 備考で明示的に整合が取れている
- 「未決事項」として残っている項目(ミス記録の保存粒度、KPM/Consistency の算出式細部、アドバイス生成ロジックの詳細)は、いずれも P2/P3 の詳細設計に属す内容であり、空セクションや TBD 放置ではなく具体的な決定事項と対比した上で意図的に先送りされている。P1完了条件「MVP全機能にFR-IDが振られ、スコープ外が明記された状態」は満たしている

## 重要度B(推奨)

### B1. 追加指標(Raw KPM・Consistency・文字種別正解率)がリスク対策表に未反映

- 対象ファイル・箇所: charter.md 3.1 の 2026-08-23 追記(P1-02)、requirements.md 3章決定事項、6章「リスクと対策」表
- 指摘内容: MVP の結果算出(#4)に Raw KPM・Consistency・文字種別正解率が追加され、requirements.md 側にも反映されているが、charter.md 6章のリスク対策表(「実装が膨らんで工程が終わらない」→「P5が8セッションを超えたら履歴画面を切ってP6へ進む」)は指標追加前のまま更新されていない。追加指標はデータ収集自体は既存ログの流用で済むとはいえ、UI表示・テストケースの増加分は工数に乗る。完走優先の方針(6章)に照らすと、これらの指標を「工数超過時に削る候補」として明記しておく方が安全
- 推奨対応: 6章のリスク対策に、Raw KPM/Consistency/文字種別正解率を優先度が低い場合の削減候補として一言追記する(P2以降でよい)
- **対応状況(2026-08-23, P2-05)**: クローズ。`charter.md` 6章に追記

### B2. 自己ベスト・履歴の「対象データ0件」時の挙動が未定義

- 対象ファイル・箇所: requirements.md FR-08/FR-09、use-cases.md UC-04/UC-05
- 指摘内容: UC-05・FR-09 は「事前条件: 1件以上のセッション結果が保存されている」を前提にしているが、選択した難易度に該当セッションが1件もない場合(他の難易度では実績があるケース)の表示仕様が受け入れ条件に書かれていない。同様に UC-04/FR-08 も履歴0件時の挙動が未記載
- 推奨対応: P2 の画面設計で「データなし」表示を定義する旨を一言申し送りとして残す。P1時点でロジック自体を確定させる必要はない
- **対応状況(2026-08-23, P2-02)**: クローズ。`docs/20_basic-design/screen-design.md` 4章で確定

### B3. charter.md 3.1 の見出し文言が「叩き台」のまま

- 対象ファイル・箇所: charter.md 3.1 見出し「MVP(叩き台 — P1で正式確定)」
- 指摘内容: 見出しは「P1で正式確定」する前提の文言だが、P1-02/P1-04 で内容は更新されているものの見出し自体は「叩き台」表記のまま据え置かれている。ゲート①通過後にこの文書の `status` を `fixed` に更新する運用と合わせて、見出し文言も「確定」に更新しないと、後から読む人がこのセクションの確定状況を誤解する
- 推奨対応: ゲート①通過が確定した時点で見出し文言と frontmatter の `status` を合わせて更新する

## 重要度C(参考)

### C1. UC-00 の認証除外根拠が ADR-001 を直接参照していない

- 対象ファイル・箇所: use-cases.md UC-00 備考
- 指摘内容: 「パスワード等の認証機能は持たない(charter.mdでスコープ外と確定済み)」とあるが、この決定の一次情報は ADR-001 であり、requirements.md NFR-05 や charter.md 3.2 は ADR-001 を明示的に引用している一方、UC-00 だけ引用先が charter.md 止まりで参照粒度が揃っていない
- 推奨対応: 次回更新時に「(ADR-001)」を併記する程度で良い。ブロッカーではない

### C2. NFR の「対応FR」列の有無が NFR 間で不揃い

- 対象ファイル・箇所: requirements.md 2章(NFR-01/02/09 には「対応FR」行があるが、NFR-03〜08 にはない)
- 指摘内容: プロジェクト全体に関わる NFR(可用性・セキュリティ・運用系)が特定 FR に紐付かないのは自然だが、行自体を省略する形と「対応FR: なし」等を明記する形が混在すると、意図的な省略か記載漏れか区別しづらい
- 推奨対応: 表記ゆれの範囲。P2以降で気になれば統一すればよい

### C3. UC-02 の「受理候補を表示する」という表現と FR-03 の「次に打つべき文字」の粒度差

- 対象ファイル・箇所: use-cases.md UC-02 基本フロー1、requirements.md FR-03
- 指摘内容: UC-02 は「ローマ字読みの受理候補を表示する」(複数候補を事前提示するようにも読める)、FR-03 は「次に打つべき文字」(単数を想起させる)と表現が異なり、UI上どちらの粒度で表示するかは実装者の解釈に委ねられている
- 推奨対応: P2 画面設計で確定すればよく、P1時点で指摘するほどの重大さはない。申し送り程度

### C4. glossary の「清音」定義が一般的な国語用法と異なる

- 対象ファイル・箇所: glossary.md 1章「清音」
- 指摘内容: 濁音・半濁音を「清音」に含める独自定義であることは明記されており内部的な曖昧さは解消されているが、一般的な国語用法(清音=濁点等のない音)と逆の定義であるため、将来的にドキュメントを読む第三者(未来の自分含む)が誤読するリスクは残る
- 推奨対応: 用語自体を変更する必要はないが、P2以降で画面表示用語として使う際は改めて注意する

## 観点別の総括

- **トレーサビリティ**: FR/NFR/UC 間の相互参照は全て実在する ID を指しており、charter の MVP 8項目も FR で過不足なくカバーされている。カバー漏れ・宙に浮いた参照は見つからなかった。問題なし
- **charter.md との整合性**: 3.1 のMVPスコープは requirements.md/use-cases.md に漏れなく反映され、3.2 のスコープ外項目とFR/UCの間に矛盾する記述は見当たらなかった。B1(リスク対策表の更新漏れ)・B3(見出し文言)のみ推奨事項として指摘
- **内部矛盾・曖昧さ**: 「文字」の粒度(判定=ローマ字1キー、分析=かな1拍)は0章の統一定義とFR-04/FR-06/FR-10/glossaryで一貫して使われており、過去指摘(中間レビューA1)への対応は現時点でも維持されている。C3のUI表現の粒度差、C4の「清音」定義は軽微な申し送り事項にとどまる
- **完了条件の充足**: 「MVP全機能にFR-IDが振られ、スコープ外が明記された状態」を満たしている。未決事項欄も空・TBD放置ではなく、P2/P3に委ねる理由とともに具体的に記載されている
- **過剰・スコープ超過**: Raw KPM・Consistency・文字種別正解率・直前拍分析等の追加はいずれも charter.md 3.1 の更新履歴と整合しており、根拠(既存ログの流用で追加コストが小さい)も明記されている。スコープ外項目(認証・お題投稿・自動お題生成等)のFR/UCへの混入も確認されなかった。B1で工数超過時のトリム対象としての明記を推奨したのみ
