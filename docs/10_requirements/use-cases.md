# ユースケース一覧

## 0. 用語(文字の粒度)

「文字」という語は文脈により2つの粒度で使う。混同を避けるため以下に統一する(レビュー指摘A1対応)。

- **入力判定の単位はローマ字1キー**: UC-02 でのタイピング中の正誤判定・確定文字/次に打つ文字の表示は、ローマ字のキー入力1つずつを単位とする
- **ミス分析の単位はかな1拍**: UC-06 のミス傾向分析(文字別ミス率など)は、ローマ字の途中経過ではなく「かな1拍(例: し、ん、っ)」を単位に集計する。1拍の入力中に複数回ローマ字キーを誤っても、分析上はその拍のミスとして扱う

## 1. アクター

| アクター | 説明 |
|---|---|
| 利用者 | Kazuki 本人。自分専用のタイピング練習として使う(認証なし、名前入力のみで識別) |

管理者・他ロールは存在しない(スコープ外)。

## 2. ユースケース一覧

| UC-ID | 名称 | 概要 |
|---|---|---|
| UC-00 | 名前を入力する | 練習を始める前に自分の名前を入力し、記録の識別に使う(パスワード等の認証はスコープ外) |
| UC-01 | 練習セッションを開始する | お題セット・出題数または制限時間を選び、タイピング練習を開始する |
| UC-02 | お題文をタイピングする | 表示されたお題文をローマ字入力し、確定文字・次に打つ文字・ミス位置がリアルタイムに反映される |
| UC-03 | セッション結果を確認する | 1セッション終了後、KPM・正確率・所要時間を確認する |
| UC-04 | 練習履歴を閲覧する | 過去に実施したセッションの一覧を確認する |
| UC-05 | 自己ベストを確認する | これまでの記録の中から最良値を確認する |
| UC-06 | ミスの傾向を分析する | どの文字を間違えやすいか、どういう間違え方をしたか、直前にどの文字を打っていたかを集計して確認する |
| UC-07 | 改善アドバイスを確認する | ミスの傾向分析に基づいたアドバイスを確認する |

## 3. ユースケース詳細

### UC-00 名前を入力する

| 項目 | 内容 |
|---|---|
| 目的 | 記録(セッション結果・ミス記録)を自分の名前に紐づけて識別する |
| トリガー | 利用者がアプリを開く(初回、または名前未入力の状態) |
| 事前条件 | なし |
| 基本フロー | 1. システムが名前入力欄を表示する<br>2. 利用者が名前を入力する<br>3. システムが名前を保持し、UC-01 に進む |
| 事後条件 | 以降のセッション・記録がこの名前に紐づく |
| 備考 | パスワード等の認証機能は持たない(charter.md でスコープ外と確定済み)。同じ名前を再入力すれば同一人物として扱う程度の簡易識別 |

### UC-01 練習セッションを開始する

| 項目 | 内容 |
|---|---|
| 目的 | 練習を始める条件(お題セット・終了条件)を決めて、お題の出題を開始させる |
| トリガー | 利用者がトップ画面で「開始」を選ぶ |
| 事前条件 | お題セットが1件以上 DB に存在する |
| 基本フロー | 1. 利用者がお題セット(難易度)を選ぶ<br>2. 利用者が終了条件(お題 N 文 / 制限時間)を選ぶ<br>3. システムが最初のお題文を表示し、UC-02 に進む |
| 事後条件 | セッションが開始され、1問目が表示されている |

### UC-02 お題文をタイピングする

| 項目 | 内容 |
|---|---|
| 目的 | お題文を正しい速さ・正確さで入力し切る |
| トリガー | UC-01 で最初のお題が表示された、または前のお題が完了した |
| 事前条件 | セッションが開始済み |
| 基本フロー | 1. システムがお題の日本語文とローマ字読みの受理候補を表示する<br>2. 利用者がローマ字キーを1つずつ入力する(IME を介さず、キー入力を直接判定する)<br>3. システムがキー入力ごとに確定文字・次に打つ文字・ミス位置を更新する(複数表記許容: し=si/shi/ci、ん=n/nn、っ=子音重ねなど)<br>4. お題文の入力が完了すると、終了条件を満たすまで次のお題を表示し 1 に戻る。満たしたら UC-03 に進む |
| 例外フロー | 誤入力時は、正しいキーが入力されるまで先に進めない。このとき**期待していたキー・実際に入力されたキー・直前に確定していたかな1拍**を、そのかな1拍のミスとしてミス記録に保持する(UC-06 の分析対象。粒度は「0. 用語」参照) |
| 事後条件 | 全お題の入力が完了し、セッションの成績とミス記録が確定している |

### UC-03 セッション結果を確認する

| 項目 | 内容 |
|---|---|
| 目的 | 直近のセッションの出来を数値で把握する |
| トリガー | UC-02 の終了条件達成 |
| 事前条件 | セッションが完了している |
| 基本フロー | 1. システムが Net KPM・Raw KPM・正確率・Consistency・所要時間を算出する<br>2. システムが結果を画面に表示する<br>3. システムが結果を DB に保存する |
| 事後条件 | 結果が DB に保存され、UC-04/UC-05 で参照可能になる |
| 備考 | セッションが終了条件を満たさずに中断された場合、結果は算出・保存しない |

### UC-04 練習履歴を閲覧する

| 項目 | 内容 |
|---|---|
| 目的 | 過去のセッション結果を振り返る |
| トリガー | 利用者が履歴画面を開く |
| 事前条件 | 1件以上のセッション結果が保存されている |
| 基本フロー | 1. 利用者が履歴画面を開く<br>2. システムが過去のセッション結果を一覧表示する(日時・KPM・正確率など) |
| 事後条件 | なし(閲覧のみ) |

### UC-05 自己ベストを確認する

| 項目 | 内容 |
|---|---|
| 目的 | これまでの最良記録を把握し、次回の目標にする |
| トリガー | 利用者が履歴画面または結果画面を開く |
| 事前条件 | 1件以上のセッション結果が保存されている |
| 基本フロー | 1. 利用者が自己ベストを見たい難易度を選ぶ(または直近プレイした難易度が既定で選ばれる)<br>2. システムが、選ばれた難易度のセッション結果から最良値(KPM最大・正確率最大)を算出する<br>3. システムが自己ベストを表示する |
| 事後条件 | なし(閲覧のみ) |
| 備考 | 自己ベストは難易度ごとに算出する(難易度が異なると出やすさが変わるため、通算では比較にならない) |

### UC-06 ミスの傾向を分析する

| 項目 | 内容 |
|---|---|
| 目的 | 「どの文字を間違えやすいか」「どう間違えたか」「直前に何を打っていたか」を把握し、正確さ向上の原因分析に使う |
| トリガー | 利用者が分析画面(または履歴画面から遷移)を開く |
| 事前条件 | 1件以上のミス記録が保存されている |
| 基本フロー | 1. 利用者が分析画面を開く<br>2. システムがかな1拍別のミス回数・ミス率を集計して表示する<br>3. システムが誤りパターン(期待していたキー→実際に入力したキーの組み合わせ)を集計して表示する<br>4. システムが直前のかな1拍とミスの関連(直前にどの拍を打っていたときにミスが多いか)を集計して表示する<br>5. システムが文字種別(清音/拗音/撥音「ん」/促音「っ」/長音)の正解率を集計して表示する |
| 事後条件 | なし(閲覧のみ) |

### UC-07 改善アドバイスを確認する

| 項目 | 内容 |
|---|---|
| 目的 | 分析結果を踏まえた具体的な練習の指針を得る |
| トリガー | 利用者が UC-06 の分析結果画面でアドバイスを見る、または分析後に自動表示される |
| 事前条件 | UC-06 の分析結果が存在する |
| 基本フロー | 1. システムが分析結果(頻出ミス文字・誤りパターン・直前文字の傾向)からアドバイスを組み立てる<br>2. システムがアドバイスを表示する |
| 事後条件 | なし(閲覧のみ) |
| 備考 | アドバイスの組み立てロジック(閾値・文言テンプレート等)は P1-02 の FR 定義および P3 詳細設計で確定する |

## 4. 決定事項・未決事項

### 決定事項(2026-08-23)

- 難易度選択は UI 上の操作とする(UC-01 で確定済み)
- 利用者識別は名前入力のみとし、認証機能(パスワード等)は追加しない(charter.md の当初方針を維持。認証への学習興味は拡張バックログとして記録)
- お題文(sentences)自体の追加・編集 UI は MVP に含めない(開発者がシードデータとして投入する運用。スコープ外バックログ「お題投稿」のまま)
- 本アプリの中心コンセプトは**タイピングの正確さを改善するための原因分析ツール**である。単なる総合スコア表示より、文字別のミス傾向・誤りパターン・直前文字との関連を記録・分析できることを優先する(UC-06/UC-07 として新規追加)
- 上記に伴い、UC-02 でミス発生時に「期待していたキー・実際に入力されたキー・直前に確定していたかな1拍」を記録する
- 「文字」の粒度は、判定=ローマ字1キー単位、分析=かな1拍単位とする(「0. 用語」参照。P1中間レビュー指摘A1対応)
- 自己ベスト(UC-05)は **KPM 最大・正確率最大** を、**難易度ごと** に算出する(→詳細は requirements.md FR-09 参照。総合スコアの単一値は作らない)

### 未決事項(P2 以降で確定)

- ミス記録の保存粒度(セッション単位の集計のみか、1ミスごとにイベントとして残すか) — テーブル設計(P2)に影響
- アドバイスの生成ロジック(ルールベースの閾値判定を想定。詳細は P3 で確定)
