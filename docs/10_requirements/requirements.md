# 機能要件・非機能要件

`FR-xx` は機能要件、`NFR-xx` は非機能要件。各項目には対応する UC-ID を併記する。

## 0. 用語(文字の粒度)

「文字」という語は文脈により2つの粒度で使う(P1中間レビュー指摘A1対応。詳細は use-cases.md 0章参照)。

- **入力判定の単位はローマ字1キー**: FR-02/FR-03 のタイピング正誤判定・リアルタイム表示は、ローマ字のキー入力1つずつを単位とする
- **ミス分析の単位はかな1拍**: FR-04 のミス記録、FR-10 のミス傾向分析は「かな1拍(例: し、ん、っ)」を単位に集計する。1拍の中で複数回キーを誤っても、分析上はその拍のミスとして扱う

## 1. 機能要件(FR)

### FR-01 お題文を表示する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-01, UC-02 |
| 内容 | システムは、選択された難易度のお題セットから1文(お題)を取得し、日本語表記(かな漢字混じり)で表示する |
| 受け入れ条件 | お題セットが1件以上あれば必ず1文が表示できる。全問終了までお題が枯渇しない(セット内でのローテーション/再利用を許容) |

### FR-02 ローマ字入力を判定する(複数表記許容)

| 項目 | 内容 |
|---|---|
| 対応UC | UC-02 |
| 内容 | システムは、表示中のお題の読み(かな)に対し、利用者が入力したローマ字キーを1つずつ判定し、正誤を確定する(IME を介さず、キー入力を直接判定する)。同一のかな1拍に対して複数のローマ字表記を正解として許容する |
| 受け入れ条件(許容する表記ゆれのカテゴリ) | 1. 清音の異表記(例: し=si/shi/ci、つ=tu/tsu、ち=ti/chi、ふ=hu/fu)<br>2. 拗音の異表記(例: しゃ=sya/sha、じゃ=zya/ja/jya)<br>3. 撥音「ん」: 単独の "n" と "nn" の両方を許容する。ただし次の入力文字によって "n" 単独では確定できないケースがある(例: "n" の次が母音や "y" の場合は "nn" が必要)<br>4. 促音「っ」: 次の子音を重ねる表記(例: がっこう→gakkou の "kk")を正解とする<br>5. 長音「ー」: 直前の母音の表記に応じた延長表記を正解とする |
| 詳細設計への申し送り | 上記はカテゴリレベルの要件であり、かな1文字ごとの厳密な受理表(全マッピング)は P3 `docs/30_detail-design/logic-spec/romaji-automaton.md` で確定する。共有テストベクタ(`shared/testdata/`)で正しさを検証する |

### FR-03 入力状態をリアルタイムに表示する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-02 |
| 内容 | システムは、入力の都度、確定済み文字・次に打つべき文字・直近のミス位置を画面上に反映する |
| 受け入れ条件 | 入力から表示更新までの遅延目標は NFR-01 で定義する |

### FR-04 ミスを記録する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-02 |
| 内容 | 誤入力が発生した際、システムは「そのミスがどのかな1拍で起きたか」「期待していたキー」「実際に入力されたキー」「直前に確定していたかな1拍」「そのかなの種別(清音/拗音/撥音「ん」/促音「っ」/長音)」を記録する |
| 受け入れ条件 | 1セッション中に発生した全てのミスが漏れなく記録される。正しいキーが入力されるまで先には進めない。同じ拍の中で複数回ミスした場合も、キー単位で全て記録した上で、分析(FR-10)ではその拍1回のミスとして扱う |
| 未決事項 | ~~記録の保存粒度(ミス1件ごとのイベントか、セッション単位の集計か)は P2 テーブル設計で確定する~~ → 解決済み。キー単位のイベント記録とする(`docs/20_basic-design/table-definition.md` TBL-05、2026-08-23) |

### FR-05 セッションの終了条件を判定する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-01, UC-02 |
| 内容 | システムは、利用者が選んだ終了条件(お題 N 文 完了 / 制限時間経過)のいずれかを満たした時点でセッションを終了する |
| 受け入れ条件 | お題数モード・制限時間モードのどちらでも、条件成立時に自動的に結果算出(FR-06)へ遷移する |
| 備考 | 終了条件を満たさずに利用者がセッションを離脱した場合、そのセッションの結果は算出・保存しない(FR-06/FR-07 対象外) |

### FR-06 セッション結果を算出する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-03 |
| 内容 | システムは、セッション終了時点までの入力ログから以下を算出する: Net KPM(正しい確定打鍵数のみを基準とした速度)、Raw KPM(ミスを含む総打鍵数を基準とした速度)、正確率、所要時間、Consistency(打鍵間隔のばらつき) |
| 受け入れ条件 | 正確率 = (正しく確定したキー入力数) ÷ (総キー入力数[ミス含む]) で算出する。同じ拍で複数回ミスした場合、その回数分を総キー入力数に含める(= ミスを繰り返すほど正確率は下がる)。Net KPM は所要時間(分)あたりの正しい確定キー入力数、Raw KPM は所要時間(分)あたりの総キー入力数(ミス含む)とする。Consistency は1キー入力ごとの入力間隔(ミリ秒)のばらつき(変動係数または標準偏差)から算出し、値が小さい(安定している)ほど良好とする |
| 未決事項 | Net/Raw KPM の算出式の細部、Consistency の具体的な統計量(標準偏差 vs 変動係数)は P3 で数式を確定する。~~上記の正確率定義は FR-04 のミス記録粒度(P2 テーブル設計)が確定した時点で再確認する~~ → 解決済み。総キー入力数 = `correctKeyCount + missRecords.length` として算出する(`docs/20_basic-design/api-spec.yaml`、2026-08-23) |

### FR-07 セッション結果を保存する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-03 |
| 内容 | システムは、算出した結果(Net KPM・Raw KPM・正確率・Consistency・所要時間・日時・利用者名)と、そのセッション中のミス記録(文字種タグ含む)を PostgreSQL に保存する |
| 受け入れ条件 | 保存後、履歴(FR-08)・自己ベスト(FR-09)・ミス分析(FR-10)から参照できる |

### FR-08 練習履歴を一覧表示する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-04 |
| 内容 | システムは、保存済みの過去セッション結果を新しい順に一覧表示する |
| 受け入れ条件 | 日時・KPM・正確率・所要時間が一覧の各行に表示される |

### FR-09 自己ベストを表示する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-05 |
| 内容 | システムは、保存済みのセッション結果を**難易度ごとに**集計し、指標ごとの最良値(Net KPM 最大・正確率最大)を算出して表示する |
| 受け入れ条件 | 異なる難易度のセッション結果を混在させて比較しない。難易度を指定して自己ベストを問い合わせられる |

### FR-10 ミスの傾向を分析する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-06 |
| 内容 | システムは、保存済みのミス記録(FR-04)を集計し、次の4観点を表示する: (1) かな1拍別のミス回数・ミス率、(2) 誤りパターン(期待していたキー→実際に入力したキーの組み合わせ)別の発生回数、(3) 直前のかな1拍別のミス発生率、(4) 文字種別(清音/拗音/撥音「ん」/促音「っ」/長音)の正解率 |
| 受け入れ条件 | 各観点は多い順にソートされ、上位を確認できる |

### FR-11 改善アドバイスを表示する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-07 |
| 内容 | システムは、FR-10 の分析結果のうち発生率・回数が高い項目に基づき、練習の指針となるアドバイス文を表示する |
| 未決事項 | アドバイスの生成ロジック(閾値・文言テンプレート)は P3 詳細設計で確定する。P1 では「分析結果に基づき機械的に生成する」ことのみを要件とする |

### FR-12 利用者を識別する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-00 |
| 内容 | システムは、利用者が入力した名前を記録の識別キーとして使用する。パスワード等の認証は行わない |
| 受け入れ条件 | 同じ名前を入力した場合、同一人物の記録として履歴・自己ベスト・ミス分析に反映される |

### FR-13 お題セット(難易度)を選択する

| 項目 | 内容 |
|---|---|
| 対応UC | UC-01 |
| 内容 | システムは、DB に保持された難易度別のお題セットを利用者が選択できるようにする |
| 受け入れ条件 | 難易度選択 UI から選んだセットに属するお題のみが FR-01 で出題される |
| 備考 | お題文自体の追加・編集 UI は MVP に含めない(use-cases.md 決定事項参照。開発者によるシードデータ投入のみ) |

## 2. 非機能要件(NFR)

### 性能

#### NFR-01 入力反応性

| 項目 | 内容 |
|---|---|
| 対応FR | FR-03 |
| 内容 | キー入力から画面反映(確定文字・次の文字・ミス位置の更新)までの遅延は 50ms 以内とする |
| 根拠 | 人間が遅延を知覚し始める一般的な目安(100ms)の半分。Vue のリアクティビティとローカルでの入力判定であれば通常達成可能 |
| 検証方法 | P6 テスト実施時、ブラウザ開発者ツールでの計測、または簡易な計測用ログで確認する |

#### NFR-02 画面表示速度

| 項目 | 内容 |
|---|---|
| 対応FR | FR-01, FR-08, FR-09, FR-10 |
| 内容 | Render 無料枠のコールドスタート(NFR-03 参照)を除き、画面遷移・データ取得は体感で待たされない範囲(目安2秒以内)に収める |
| 備考 | 個人学習用途のため厳密な性能試験は行わず、体感確認にとどめる |

### 可用性

#### NFR-03 可用性の方針

| 項目 | 内容 |
|---|---|
| 内容 | Render 無料枠を採用し、一定時間アクセスが無い場合のサービススリープ、および次回アクセス時のコールドスタート遅延(数十秒程度)を許容する |
| 根拠 | 個人専用アプリであり、常時起動の可用性を保証するコストをかける必要がない(charter.md 5章「コストは Render 無料枠の範囲で収める」と整合) |
| 対象外 | 稼働率(SLA)の数値目標は設定しない |

### セキュリティ

#### NFR-04 通信の保護

| 項目 | 内容 |
|---|---|
| 内容 | 公開 URL への通信は HTTPS を使用する(Render のデフォルト機能で満たす) |

#### NFR-05 入力値の保護

| 項目 | 内容 |
|---|---|
| 内容 | 名前入力・タイピング入力を含む全ての利用者入力は、SQL インジェクション・XSS を防ぐ形で扱う(JPA のパラメータバインディング、フロントでのエスケープ処理) |
| 備考 | 認証を行わないため(ADR-001)、なりすまし対策は行わない。同じ名前を入力すれば誰でもその記録を閲覧・追記できる点はリスクとして許容する(個人専用・非公開運用のため) |

#### NFR-06 秘匿情報管理

| 項目 | 内容 |
|---|---|
| 内容 | DB接続情報等の秘匿情報はソースコードにハードコードせず、環境変数(Render の環境変数機能)で管理する |

### 運用

#### NFR-07 ログ

| 項目 | 内容 |
|---|---|
| 内容 | アプリケーションの起動・エラー発生をログに出力する。個人開発のため高度な監視基盤(APM等)は導入しない |

#### NFR-08 バックアップ

| 項目 | 内容 |
|---|---|
| 内容 | PostgreSQL のバックアップは Render Managed Postgres の標準バックアップ機能に委ねる。個人利用のためリストア手順の詳細化・訓練は行わない |

#### NFR-09 DB障害時の挙動

| 項目 | 内容 |
|---|---|
| 対応FR | FR-01, FR-07 |
| 内容 | お題取得(FR-01)やセッション結果保存(FR-07)で DB 接続に失敗した場合、システムはエラー画面を表示し、利用者にその旨を伝える。保存処理は失敗時に部分的なデータを残さない(トランザクション単位で成功/失敗を確定する) |
| 備考 | 個人開発のため自動リトライ・フェイルオーバー等の高度な対策は行わない |

## 3. 決定事項(2026-08-23, P1-02/P1-03)

- FR-09(自己ベスト)の指標は **KPM 最大** と **正確率最大** を、**難易度ごと** に算出する。総合スコアの単一値は作らない(本アプリの主眼はミス分析であり、単一スコアへの圧縮は目的に合わない。難易度をまたいだ通算比較は意味を持たないため難易度別とする)
- タイピング品質の指標として、既存の Net KPM・正確率に加え **Raw KPM・文字種別正解率・Consistency(打鍵間隔のばらつき)** を MVP(FR-04/FR-06/FR-07/FR-10)に追加する。いずれも既存のミス記録・打鍵ログから算出でき、追加の計測項目(タイムスタンプ・文字種タグ)のみで実現できるため採用した
- NFR-01(入力反応性)は 50ms 以内とする
- NFR-03(可用性)は Render 無料枠のスリープ・コールドスタートを許容し、稼働率の数値目標は設定しない
- 「文字」の粒度は判定=ローマ字1キー単位、分析=かな1拍単位とする(P1中間レビュー指摘A1対応)
- 正確率(FR-06)は「正しく確定したキー入力数 ÷ 総キー入力数」とし、同じ拍での複数回ミスは総キー入力数にすべて含める
- セッションが終了条件を満たさず中断された場合、結果は算出・保存しない(FR-05/FR-07)
- ローマ字入力は IME を介さず、キー入力を直接判定する(FR-02)

## 4. 拡張バックログ(指標)

MVP には含めないが、診断の質を上げる候補として記録しておく(理由: 設計判断や実装コストが相対的に重い)。

| 指標 | 内容 | 見送り理由 |
|---|---|---|
| リカバリータイム | ミス直後、数文字分の入力速度が低下するかどうか | 前後の打鍵時間を比較するロジック設計が必要 |
| 思考停止(反応時間) | 新しい文字/お題提示から最初のキー入力までの遅延 | 「正常な考慮時間」との閾値定義が必要 |
| 直前2文字(文脈)でのミス傾向 | 直前1文字だけでなく直前2文字の組み合わせで集計 | データ量が増え、有意な傾向が出るまでのセッション数も増える |
| 手/指別のミス傾向 | キーボード配列上の位置(左手/右手等)に基づく集計 | キー配列とローマ字の対応マッピングの追加設計が必要 |
